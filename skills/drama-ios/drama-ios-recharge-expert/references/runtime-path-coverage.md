# Runtime path coverage

Load this reference only for entry, route, runtime-host, UI, notification, or cross-path propagation work. Use only the applicable sections; the current kernel and source remain authoritative for business facts.

## Exact host and route map

Extend the behavior ledger with a requested-role → exact-runtime-host mapping. Prove each included or excluded role from current registration, construction, presentation, routing, and ownership call sites. Do not infer a live host from a class name, folder, comment, or the first similar path found.

For every task-named family, resolve only the applicable baseline handoff:

- legacy, new, and black-user half-window paths;
- old, new, and black full-page wallet paths;
- independent gift paths versus similarly named package/product branches inside another flow;
- H5 and RN entry/result paths;
- UI success/error presentation and IM/system-message side effects.

Path-family words are hard scope. A modern host cannot substitute for a requested legacy caller, and an extra family must not displace a named one. If two product-role labels might be reversed, stop the contract until live call sites disambiguate them.

## Producer-to-consumer closure

For each value or signal that must cross a path, record:

```text
selection/model producer → entry/start handoff → carrier/context → channel-specific sink → result/retry/cleanup consumer
```

Search reads as well as writes. A producer may be server data, preselected configuration, controller state, or an upstream handoff rather than a dedicated selection UI. Absence of one producer shape is not evidence that another family cannot receive or forward the value.

For notifications/events, identify the declaration, every task-relevant producer, consumer, payload construction, thread/source differences, and cleanup/unsubscribe behavior. Exact static search cannot prove there are no dynamic registrations, string routes, or repository-external H5/RN callers; record that limitation and avoid broad absence claims.

## Cross-path and UI/IM boundaries

- Trace the same semantic value through every requested family before declaring one `not applicable`; cite concrete control-flow evidence for any exclusion.
- Preserve Component/Router/Manager/Flow/Module ownership. Do not relocate routing or completion policy into a convenient view.
- Treat visible removal, route dismissal, terminal completion, notification delivery, and state cleanup as separate events unless exact source proves they share an owner.

## Closure check

Before patching and again against the diff, verify that every requested host and propagation row has an explicit action and static validation. A shared helper does not prove each caller is wired. For a no-match claim, record revision, searched paths, and exact identifiers and phrase the conclusion as an unresolved coverage gap.
